# AI Student Support Assistant

Answers college-related questions from regulations, syllabus, FAQs, and
notices, using a RAG + Tools + Memory architecture on top of Google Gemini.

## Architecture

- **RAG** (`rag.py`) — loads every `.txt` file in `knowledge_base/`, chunks
  it by paragraph, embeds chunks with `sentence-transformers`, and indexes
  them with FAISS for semantic search.
- **Tools** (`tools.py`) — deterministic helpers the LLM shouldn't guess at:
  today's date, days remaining until a deadline, exact FAQ keyword search,
  and a scan of `notices.txt` for upcoming dated deadlines.
- **Memory** (`memory.py` + `database.py`) — per-session conversation
  history stored in SQLite, replayed into every prompt so the assistant
  stays consistent across a multi-turn conversation.
- **Agent** (`agent.py`) — combines all three and calls Gemini.
- **API** (`app.py`) — FastAPI app exposing everything over HTTP.

## Setup

1. Create and activate a virtual environment:
   ```bash
   python -m venv venv
   source venv/bin/activate      # Windows: venv\Scripts\activate
   ```

2. Install dependencies:
   ```bash
   pip install -r requirements.txt
   ```

3. Copy `.env.example` to `.env` and add your Gemini API key:
   ```bash
   cp .env.example .env
   ```
   Get a key at https://aistudio.google.com/apikey

4. (Optional) Replace the sample files in `knowledge_base/` with your
   actual college's regulations, syllabus, FAQs, and notices.

5. Run the server:
   ```bash
   uvicorn app:app --reload
   ```
   This starts the API at `http://127.0.0.1:8000` and creates
   `student_support.db` automatically on first run.

## Using the API

Open `http://127.0.0.1:8000/docs` for the interactive Swagger UI, or call
it directly:

```bash
curl -X POST http://127.0.0.1:8000/ask \
  -H "Content-Type: application/json" \
  -d '{"session_id": "student123", "question": "What is the attendance requirement?"}'
```

Ask a follow-up in the *same* session and the assistant will remember the
earlier exchange:

```bash
curl -X POST http://127.0.0.1:8000/ask \
  -H "Content-Type: application/json" \
  -d '{"session_id": "student123", "question": "What if I am below that percentage?"}'
```

Other endpoints:
- `GET /history/{session_id}` — view a session's conversation memory
- `DELETE /history/{session_id}` — clear a session's memory
- `GET /qa-log` — view the permanent log of all questions/answers
- `GET /categories` — list available knowledge base categories

## Notes

- `session_id` should be generated by your frontend (e.g. a UUID stored in
  local storage or a login-based user ID) and sent with every request so
  memory is scoped correctly per student.
- The knowledge base files use a blank-line-separated paragraph format for
  chunking — keep that structure if you add more content, so retrieval
  stays focused.
- `notices.txt` uses `NOTICE DATE:` and `TITLE:` markers, and any
  `YYYY-MM-DD` dates inside an entry are picked up by
  `extract_upcoming_deadlines()` in `tools.py`.
